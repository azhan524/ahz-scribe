# Ahz Scribe 执行力记分卡

一句话：**跑一遍，把"变强了多少"变成分数**。改完代码不用凭感觉，跑这个就有数字。

## 怎么跑

```powershell
# 正常档（用 config.json 里的 max_steps），跑全部题目 + 护栏，约 2-3 分钟
powershell -ExecutionPolicy Bypass -File devtools\scorecard\run-scorecard.ps1

# 只跑某题（S1..S7 / H1 / SA / S4_tight / H1_tight / G）
powershell -File devtools\scorecard\run-scorecard.ps1 -Only H1

# 换模型跑（比如本地小模型，会慢很多）
powershell -File devtools\scorecard\run-scorecard.ps1 -Provider ollama-local -Model qwen3.5:4b
```

结果打印成表格，同时写进 `result.csv` 和 `score.json`。跑完会自动删掉 `_app` / `_app_tight`（里面复制过 config，含 API Key）；
每题的完整过程日志留在 `runs\` 里（不含 Key）。

> 记分卡自身的两个坑（已修）：① 有些环境里 PowerShell 5.1 的 `Get-FileHash` 加载不出来，会让"改没改测试/动没动冻结文件"的
> 校验静默失效 —— 现在改成纯 .NET SHA256；② `score.json` 以前记的是仓库配置里的模型名，用 `-Model` 覆盖时会记错 —— 现在记实际用的。

## 评分口径（100 分）

| 维度 | 分值 | 怎么算 |
| --- | --- | --- |
| 完成率 | 45 | 通过题数 / 总题数 |
| 一次通过 | 15 | (1 − 撞步数上限的比例) × 15 |
| 效率 | 15 | 平均工具调用数：≤12→15，≤20→12，≤35→9，≤60→6，否则 3 |
| 稳定 | 15 | 15 − 2×工具报错 − 5×(改测试 / 动冻结文件 / 超时)，下限 0 |
| 速度 | 5 | 平均用时：≤20s→5，≤40s→4，≤90s→2，否则 1 |
| 成本 | 5 | 平均 token：≤3000→5，≤6000→4，≤12000→2，否则 1 |

护栏（G）**不进题数、也不进总分**，单独一行展示——安全不能用分数换。

注意：**单跑一题的分数没有可比性**（基础分占大头），要有意义就跑全量。因此 `-Only` 的单题跑**不写进 `history.csv`**（否则它会让下一次的「与上次对比」算出假分差：实测出现过 `-Only` 跑出 100 分、把真基线挤成对照组的假「+42 分进步」）。

## 基线（2026-10-10，deepseek-flash，max_steps=28）

- **97 / 100**（同一天另一次 95.6，波动约 1.5 分）
- 完成 11/11、撞顶 0、工具报错 0、越界 0、改测试 0
- 唯一丢分：效率（平均 13 次工具调用，满分档是 ≤12）
- 对照：本地 `qwen3.5:4b` 跑 S1/S5/S6 也都通过，但每题 90–180 秒、S6 出现 2 次工具报错 → **框架没问题，差距在模型速度与稳定性**

## 维护这个记分卡自己的规矩

- 每道题都要能**客观判定**（测试/哈希），不能靠"看起来对"
- 加题时先确认**初始状态是失败的**（否则等于送分）
- 修改题目后，先跑一遍"标准答案"确认可解（`devtools/bigbench/reference-fix.py` 是 S4 的标准答案）
- 判定要能识别作弊：S4/H1 校验 tests 目录哈希，S7 校验冻结文件哈希
